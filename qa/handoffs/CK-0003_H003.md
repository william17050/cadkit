## Summary Of Changes
This handoff addresses the one remaining product-behavior question surfaced in
`CK-0003_R001`.

Change implemented:
- in the generic live hover path and the QA bridge mirror, exact
  `perpendicular_snap()` now runs before `tracking_snap()`
- perpendicular tracking remains available as the fallback when no exact on-entity
  perpendicular foot is within snap radius
- parallel tracking behavior is otherwise unchanged

Affected files:
- `crates/ui-egui/src/app.rs`
- `crates/ui-egui/src/app/qa_automation.rs`

Intent:
- if the cursor is genuinely close to the actual perpendicular foot on a Line/Polyline
  target, CadKit should now resolve the exact on-entity foot instead of the looser
  construction-line tracking point
- if no exact foot is close enough, the tracking-guide behavior should still be
  available

## Files Changed
- `crates/ui-egui/src/app.rs`
- `crates/ui-egui/src/app/qa_automation.rs`

## Expected Behavior
- The `CK-0003_R001` line-target perpendicular repro should now resolve to the true
  on-entity foot when the cursor is within snap radius of it.
- Circle-target perpendicular behavior should remain unchanged.
- Tangent and nearest behavior should remain unchanged.
- If the cursor is not close enough to a true perpendicular foot, perpendicular
  tracking may still resolve as the fallback construction aid.

## Required Test Scenarios

   hover resolves to the true entity-bound foot, not the tracking-guide point.
2. Verify `click_world_snapped` in that same line-target case creates geometry ending
   at the true perpendicular foot.
3. Re-run the circle-target perpendicular case from `CK-0003_R001` and verify it
   remains correct.

   regression.

6. Use the bridge `ortho` action rather than editing `prefs.json`.
7. Clean shutdown through the bridge `quit` path.
