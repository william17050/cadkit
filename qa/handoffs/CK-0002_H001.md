## Summary Of Changes
This handoff extends the in-app QA bridge with snap-aware hover and click actions so Claude Code can verify snapping behavior without OS-level input injection.

New bridge actions:
- `hover_world_snapped`
- `click_world_snapped`

These actions use CadKit's internal snap-resolution pipeline instead of raw point delivery.

## Files Changed
- `crates/ui-egui/src/app/qa_automation.rs`
- `scripts/cadkit_qa_bridge.py`
- `docs/QA_AUTOMATION_BRIDGE.md`

## Expected Behavior
- `hover_world_snapped` should update `state.json` with:
  - resolved `hover_world`
  - resolved `hover_snap_kind`
- `click_world_snapped` should deliver the resolved snapped point through normal tool point handling.
- Raw `click_world` remains available and continues to bypass snapping by design.

## Required Test Scenarios
1. Start `LINE` and verify endpoint snap by hovering and clicking near an existing endpoint.
2. Verify midpoint or center snap on simple geometry where the target is unambiguous.
3. Verify intersection snap by drawing two crossing lines, then hovering and clicking near their crossing.
4. Verify ortho plus snap interaction on a line continuation case.
5. Confirm `hover_snap_kind` in `state.json` matches the resolved snapped result.
6. Confirm raw `click_world` and snap-aware `click_world_snapped` differ when aimed near, but not exactly on, a snap target.

## Known Limitations
- This still does not validate literal desktop hover ergonomics, cursor icons, or OS input plumbing.
- Unsupported interaction modes should return explicit bridge errors.
- Product behavior outside the snap chain is not the focus of this work item.
