## Expected Behavior
- `hover_world_snapped` should resolve each tested snap mode to the correct world point and report the matching `hover_snap_kind`.
- `click_world_snapped` should deliver the same resolved point into the active drawing command and create geometry consistent with that snap.
- `OSMODE` should allow reliable isolation of individual snap kinds so results are unambiguous.
- `nearest` should only resolve when explicitly enabled, since it defaults off in CadKit preferences.
- `click_world` should remain raw and continue to differ from `click_world_snapped` when aimed near, but not exactly on, a valid snap solution.

## Required Test Scenarios
1. Quadrant snap on a simple circle with `OSMODE 16`: verify hover and delivered geometry land on the intended east, west, north, or south quadrant point and report `quadrant`.
2. Perpendicular snap with `OSMODE 128`: create a clear base point and a target line so the perpendicular foot is unique; verify both hover and delivered geometry resolve to that foot and report `perpendicular`.
3. Tangent snap with `OSMODE 256`: use a line continuation or equivalent from an external point to a circle so the tangent solution is unambiguous; verify hover and delivered geometry resolve to a real tangent point and report `tangent`.
4. Nearest snap with `OSMODE 512`: verify hover and delivered geometry resolve to the closest point on a target entity and report `nearest`.
5. Raw-versus-snapped comparison for at least one of the above: use identical approximate input with `click_world` and `click_world_snapped` and confirm the raw click does not silently adopt the snap result.
6. Negative control for each isolated mode: with the same `OSMODE` still active, aim at a location that should not produce that snap and confirm CadKit either resolves `none` or falls back in a way consistent with the live command state.
7. Clean shutdown through the bridge `quit` path after the scenario set completes.

## Known Limitations
- This cycle still does not validate literal desktop cursor ergonomics, icon changes, or OS-level pointer behavior.
- Some snap kinds may require deliberate geometry setup to avoid multiple mathematically valid candidates; if ambiguity appears, adjust geometry rather than treating the first ambiguous result as a product bug.
- Parallel tracking is available in CadKit and the bridge, but it is not the primary focus of this handoff unless it blocks or overlaps the perpendicular setup.
