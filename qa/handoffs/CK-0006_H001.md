## Summary Of Changes
This handoff adds a bridge-managed QA session snapshot/restore workflow for
preference-backed test settings.

Change implemented:
- added a QA-scoped preference snapshot type containing the persisted settings that
  matter to automated QA:
  - snap master toggle
  - all snap mode flags
  - Ortho
  - Polar
  - Polar angle
  - grid visibility
  - grid spacing
- added bridge commands:
  - `prefs_snapshot`
  - `prefs_restore`
- stored the snapshot under the active QA runtime root, not in Bill's global config
- exposed snapshot-active state in `state.json`
- added conditional auto-restore on bridge `quit` when a snapshot is still active

Implementation notes:
- the snapshot scope is intentionally narrower than full `AppPrefs`; it does not
  include unrelated user state such as `current_file`, `recent_files`, or
  `dim_style`
- normal prefs load still flows through `AppPrefs`; QA restore uses a dedicated
  subset apply path

## Expected Behavior
- `prefs-snapshot` captures the current QA-relevant persisted settings and marks the
  session snapshot as active.
- `prefs-restore` reapplies those captured settings, clears the active flag, and
  deletes the session snapshot file.
- if bridge `quit` is called while a snapshot is active, CadKit restores first and
  then closes.
- if no snapshot exists, `prefs-restore` fails clearly and does not corrupt state.

## Required Test Scenarios
1. Capture a baseline with `prefs-snapshot` and verify state reports the snapshot as active.
2. Mutate Ortho, Polar, Polar angle, and snap flags, then verify `prefs-restore`
   returns them to baseline.
3. Capture again, mutate again, skip explicit restore, and verify bridge `quit`
   auto-restores before close.
4. Relaunch against the same QA runtime root and verify restored values persist.
5. Verify `prefs-restore` without an active snapshot fails clearly and leaves state unchanged.
6. Reconfirm `ortho`, `polar`, `polar-angle`, and `quit` bridge commands still work.

## Known Limitations
- Snapshot scope is limited to QA-relevant persisted settings by design; it is not a
  full session capture.
- This handoff does not automate arbitrary UI-only settings beyond the defined QA
  preference subset.
