## Summary Of Changes
This handoff captures the current in-progress cabinet authoring foundation that was built directly in the working tree and is not yet committed.

Implemented in the current dirty tree:
- cabinet metadata model in `cadkit-2d-core`
  - cabinet parameters
  - cabinet views
  - cabinet part recipe rows
  - generated cabinet part evaluation
- `CabDef` attach/remove workflow for blocks
- cabinet insert parameter overrides in the Properties panel
- safeguard that blocks cabinet instance parameter editing until the block has been authored and saved through `BEDIT` / `BSAVE`
- `BMake` replace-source option
- external block save/load (`WBLOCK` / `LoadBlock`)
- block edit persistence for `dynamic_v1` and `cabinet_v1`
- cabinet behavior authoring in `BEDIT`
  - width/height-driven move/stretch/anchor/center rules
  - compound rule stacking now works, including cases like `H = Stretch Y + Move Y`
- `CabDef` rule inspector
  - lists current authored behavior bindings
  - can load a binding back into the editor controls
  - can remove one binding at a time
- `CabDef Parts` editor in `BEDIT`
  - add/remove recipe rows
  - edit part name
  - enable/disable row
  - edit formulas for qty/length/width/thickness/core/finish
  - edit face/grain/notes

Practical outcome:
- CadKit can now store cabinet-specific block metadata and evaluate generated part rows from cabinet inserts.
- The remaining product definition gap is not the code scaffold; it is the default cabinet-family recipe data and family rules.

## Expected Behavior
- A block can receive starter cabinet metadata through `CabDef`.
- In `BEDIT`, cabinet parameter defaults can be edited on the block definition.
- In `BEDIT`, selected entities can be assigned cabinet behavior rules driven by parameters like `W` and `H`.
- Multiple rules can coexist on the same geometry for the same driver when the behavior meaning differs.
- In `BEDIT`, authored behavior bindings are visible in the inspector and can be loaded or removed individually.
- In `BEDIT`, cabinet part recipe rows can be authored directly on the block definition.
- On cabinet inserts, generated parts continue to evaluate from the block recipe plus instance parameter overrides.
