## Summary Of Changes
This handoff records the committed `CK-0002` bundle after QA verified both the snap-aware bridge work and the follow-up product fix.

The change set does two things:
- tightens point-type snap acquisition from the old shared `PICK_RADIUS` to narrower snap-specific radii
- fixes the real Ortho-plus-object-snap continuation bug (`BUG-002`) where a correctly resolved snap could be overwritten by a second plain ortho projection

The `BUG-002` fix was applied consistently in:
- the real interactive hover path
- the real interactive click path
- the QA bridge mirror path

## Expected Behavior
- Endpoint, midpoint, center, quadrant, and intersection snaps should require the pointer to be meaningfully closer than before.
- Entity selection behavior should remain unchanged; the tighter radii apply to snap acquisition, not general entity picking.
- During `LINE` or `POLYLINE` continuation with Ortho enabled, an in-range object snap on the ortho axis should be honored instead of being replaced by a plain axis projection.
- If no qualifying ortho candidate exists, Ortho should still fall back cleanly to plain axis projection.
- `hover_world_snapped` and `click_world_snapped` should mirror the same resolved world point and snap kind as the live app logic.

## Required Test Scenarios
1. Verify endpoint snap near vs. moderate offset so a near target still snaps and a moderate offset that would have snapped under the old radius now does not.
2. Verify midpoint snap with the same near vs. moderate comparison.
3. Verify intersection snap with the same near vs. moderate comparison.
4. Verify raw `click_world` and snap-aware `click_world_snapped` produce different geometry when aimed near, but not exactly on, a snap target.
5. Verify Ortho plus object snap during line continuation honors the real snap target for both hover resolution and actual placed geometry.
6. Verify an Ortho continuation case with no qualifying candidate falls back to plain axis projection with `snap: none`.
7. Verify app close through the bridge `quit` path still exits cleanly.
