## Expected Behavior Guidance

### Known Implemented Behavior
- A native windowed app should build from the workspace and launch from `target/debug/cadkit`.
- Source inspection and current docs indicate support for line drawing, selection, drag selection, delete, undo, redo, zoom, pan, command input, and viewport rendering.

### Behavior Inferred From Source Inspection
- Command activation for simple geometry likely works through the command line, toolbar, or both.
- Selection should include click selection and a marquee flow with window/crossing semantics.
- `Esc` likely cancels active modes, but exact sequencing and retained-state details are unconfirmed.

### Unconfirmed Before Playtest
- Exact prompt text and whether it matches the tester's CAD expectations.
- Whether a draw command remains active after creating one line.
- Whether add/remove selection modifiers are available and discoverable.
- Whether drag-selection direction changes selection semantics in practice.
- Whether delete/undo/redo preserve selection state cleanly.

### AutoCAD Reference Only
- AutoCAD may be used for comparison of command feel, cancellation expectations, and selection semantics, but not as a reason to fail undocumented CadKit behavior.

## Scenario Notes

### CK-0001-T001 — Build and launch
- Build CadKit from a clean or known state.
- Launch the application.
- Confirm the main window appears.
- Confirm the application remains responsive for at least basic interaction.
- Record startup warnings, errors, and terminal output.
- Confirm whether closing the window exits cleanly.

### CK-0001-T002 — Initial viewport behavior
- Observe the initial viewport.
- Move the pointer through the viewport.
- Test zoom in and zoom out using the normal user control.
- Test pan using the normal user control.
- Confirm the view updates without visible corruption or stale rendering.
- Note whether zoom centers on the pointer, viewport center, or another point.
- Note whether pan direction and sensitivity feel predictable.

### CK-0001-T003 — Create simple geometry
- Use the simplest currently supported drawing workflow to create at least three separate line entities.
- Record command activation method, prompt sequence, click sequence, preview behavior, how the command completes, whether it remains active afterward, and `Esc` / `Enter` behavior.

### CK-0001-T004 — Basic click selection
- Select one entity by clicking it.
- Select empty space.
- Select another entity.
- Test adding to selection if supported.
- Test removing from selection if supported.
- Press `Escape` during or after selection.
- Record selection highlighting and retained-selection behavior.

### CK-0001-T005 — Window or crossing selection
- Test any drag-selection behavior currently present.
- Record drag direction, rectangle appearance, when the rectangle becomes visible, which entities are selected, whether fully enclosed and crossed entities behave differently, mouse-release behavior, and `Escape` cancellation behavior.
- If window or crossing selection is absent, record that clearly rather than treating it as a failure against undocumented behavior.

### CK-0001-T006 — Delete and undo
- Select an entity using normal input.
- Delete it through the ordinary user-facing method.
- Undo the deletion.
- Confirm whether the entity returns.
- Record retained selection state and visual feedback.
- Test redo if it currently exists.

### CK-0001-T007 — Stability pass
- Perform a short mixed interaction sequence: draw geometry, zoom, pan, select, deselect, delete, undo, cancel a command.
- Record crashes, freezes, graphical artifacts, stuck command modes, or unexpected retained state.
