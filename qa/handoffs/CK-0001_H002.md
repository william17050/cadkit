## Summary Of Changes
This handoff formalizes the in-app QA automation bridge used to unblock behavioral testing on Bazzite KDE Wayland where OS-level synthetic input was unavailable.

The bridge is:
- explicit opt-in via `CADKIT_QA_DIR`
- file-based, not socket-based
- implemented inside CadKit, not through privileged host input injection
- wired to shared app logic for Escape/Delete and existing viewport/selection helpers

The bridge supports the current `CK-0001` baseline scenarios:
- launch/recovery handling
- command execution
- exact-coordinate point delivery
- click selection
- window/crossing drag selection
- delete, undo, redo
- zoom and pan
- app-level close request

## Expected Behavior
- When `CADKIT_QA_DIR` is unset, CadKit behavior is unchanged.
- When `CADKIT_QA_DIR` is set, CadKit should:
  - create `commands/`, `processed/`, `results/`, and `state.json` under the given root
  - process queued JSON command files in filename order
  - write per-command JSON result files
  - continuously publish current machine-readable state
- `scripts/cadkit_qa_bridge.py` should enqueue commands and wait for result files.

## Known Limitations
- `click_world` delivers raw world coordinates and does **not** exercise the normal snap chain.
- The bridge does not yet validate real hover ergonomics, pointer icons, or OS-level focus behavior.
- Unsupported interaction modes should return explicit errors rather than silently approximating behavior.
