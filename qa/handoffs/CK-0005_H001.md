## Summary Of Changes
This handoff separates the old single directional-constraint flag into two user-facing
features:

- `Ortho` is now a true orthogonal lock on `F8`
- `Polar` remains increment-angle tracking on `F10`
- if both are enabled, `Ortho` takes precedence over `Polar`

Implementation details:
- added a new persistent flag `axis_ortho_enabled`
- kept the existing `ortho_enabled` field as the internal Polar flag to avoid a broad
  refactor during this feature pass
- centralized precedence in `ortho_snap()` so every tool using directional
  constraints inherits the same `Ortho > Polar` rule
- generalized line/polyline continuation candidate resolution so snap-assisted
  continuation follows the active guide direction for both Ortho and Polar
- updated the QA bridge to expose separate `ortho` and `polar` controls and report
  both states distinctly in `state.json`

## Expected Behavior
- With `Ortho` off and `Polar` off, directional input is unconstrained.
- With `Polar` on and `Ortho` off, directional input follows the configured polar
  increment.
- With `Ortho` on and `Polar` off, directional input locks to horizontal or vertical.
- With both on, `Ortho` wins.
- The same rule applies to live preview, delivered geometry, and snap-assisted
  line/polyline continuation.
- QA bridge commands `ortho` and `polar` each control only their own mode.
